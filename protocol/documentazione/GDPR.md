# GDPR · Privacy by Design

- Il passaporto alimentare è cifrato lato utente: il ristorante non memorizza
  dati sanitari.
- L’incrocio avviene sul server del protocollo. In uscita resta un booleano
  a tre stati.
- Le identità `SP-DEMO-*` sono finte, etichettate come tali, servono solo a
  verificare il motore.
- I passaporti reali sono legati all’account (`user_id`) e non sono elencabili.
- Base giuridica prevista: consenso esplicito + interesse vitale (allergie).
- Destinazione futura: database UE, stessi JSON di `protocol/dati`.
